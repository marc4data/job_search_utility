# Verified Skills — [Your Name]

**This is the most important file in the system.** It is the single source of
truth for what you have actually done. The process-opportunities skill reads it
before writing any resume or cover letter, and will NOT claim a tool, skill, or
domain for you unless it appears here against the relevant company.

Without this file, the tool will confidently invent experience to match a job
description. With it, every claim is grounded in something you really did.

> The setup-profile skill builds this from your interview. Keep it updated as
> you remember more. Copy this file to `verified_skills.md`.

## Critical rule
Never attribute a technology, skill, or domain to a company unless it is listed
below under that company. When in doubt, leave it out.

## Tools / skills I have NEVER used (never claim these)
List anything you want to be sure never shows up — especially tools that are
adjacent to yours and easy to conflate.
- Example: Tool X (never used)
- Example: Framework Y (evaluated once, never deployed — treat as not used)

## Skills that are PORTFOLIO / LEARNING ONLY (claim only with that attribution)
Tools you've used in side projects or courses but never professionally. These
may be mentioned, but ALWAYS attributed to the portfolio/personal project —
never to an employer.
- Example: Snowflake — portfolio project only, not at any employer
- Example: Spark — coursework only
